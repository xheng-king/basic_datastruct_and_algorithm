## 算法错误日志

有线索用线索，没线索闯右子树最左（顺序）或左子树最右（逆序）
但是闯的时候循环条件是`p->ltag == 0`，代表有左孩子，而不是
`p->lchild != NULL`，因为此时二叉树已被线索化，不能根据指针是否为空判断左孩子是否存在

`if(current->index == index || current == NULL)`与`if(current == NULL || current->index == index)`可不一样
前者current为空直接会对NULL指针解引用导致段错误，后者是对的

`inthread`函数修改pre指向的结点可以，但是在`creat_inthread`函数中，pre本身可没被修改，而`creat_inthread`主要功能就是给`thread`函数擦屁股，就是置中序访问的最后一个结点pre的rchild为空且rtag为1，而教材上是用了c++的引用功能

inthread这个中序线索化函数，若当前结点左孩子为空则置为pre，这没问题，但是若pre的右孩子为空则置为p，缺了一个条件，即pre本身不为空。若缺少该条件，初始时pre为空就会导致错误

## 二叉树线索化应用场景思考

线索二叉树对于插入删除节点操作，需要重建线索，这往往依赖重新遍历整棵树
因此尽量在无需变动树，同时有着大量对找树的结点前驱和后继时，使用二叉线索树

## 反思

### 1.（线索）二叉树的结构体定义
不要像图一样，树结点和树两个单独声明两种结构  
就声明树的结点即可，根结点就让它直接代表整颗二叉树

### 2..线索化:
inthread：中序递归函数，若当前结点非空，则先线索化左子树，再线索化自身(设置p和pre)，最后线索化右子树  
creat_inthread：擦屁股函数，负责提供pre指针供inthread使用并修改，最后将pre指向的中序序列最后的结点的rchild置空，rtag置1

### 3.遍历线索树
first_node：查找一颗（子）树第一个中序结点，即返回最左下的结点
next_node：查找当前结点在中序序列中的下一个结点，即有rtag就用rchild，没有rtag就用first_node找右子树第一个中序结点
